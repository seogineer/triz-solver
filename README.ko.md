# TRIZ Solver

[English](README.md)

공학·제품 설계의 트레이드오프를 **TRIZ**로 푸는 Claude Code 플러그인입니다. 문제를 모순으로 구조화해 해결 아이디어를 제안합니다. **기술적 모순**(한 특성을 개선하면 다른 특성이 나빠짐)은 고전 모순 행렬과 40 발명 원리로, **물리적 모순**(한 특성이 커야 하면서 작아야 함)은 분리 원리로 풉니다.

서버·DB·API 키가 필요 없습니다. 추론은 Claude가, 조회는 표준 라이브러리만 쓰는 작은 Python 스크립트가 맡기 때문에 행렬 셀 값, 분리 유형, 원리 번호를 기억으로 지어내지 않습니다.

> **상태: v0.3 (정식 공개 전).** 기술적 모순과 물리적 모순, 모호한 입력을 위한 구조화 인터뷰, Markdown 보고서 저장을 지원하고, 원리마다 4건씩 모두 160건의 산업 사례를 비유로 씁니다. 결과를 활용하기 전에 [데이터 상태](#데이터-상태)를 확인하세요.

## 설치

```
/plugin marketplace add seogineer/triz-solver
/plugin install triz-solver@triz-solver
```

로컬에서 시험하려면 `claude --plugin-dir .`

## 사용

```
/triz 우산은 비를 막으려면 커야 하고 들고 다니려면 작아야 해요
/triz 전동 킥보드 최고 속도를 올리면 배터리가 너무 빨리 닳아요 --save
```

세션에서 `/triz`가 인식되지 않으면 전체 이름 `/triz-solver:triz`를 쓰세요. `--save`를 붙이거나 "저장해줘"라고 하면 현재 디렉토리에 `triz-report-YYYYMMDD-<주제>.md`로 분석을 저장합니다.

`/triz` 없이 문제를 자연어(한국어·영어)로 설명해도 `triz-analysis` 스킬이 자동으로 켜집니다. 답변은 입력한 언어를 따릅니다.

**기술적 모순** ("X를 개선하면 Y가 악화된다"):

1. "X를 개선하면 Y가 악화된다" 형태로 다시 쓰고 사용자에게 확인
2. X, Y를 39개 공학 파라미터에 매핑 (각 1~3개, 근거 포함)
3. 후보 조합을 모두 행렬에서 조회 (`lookup.py matrix`)
4. 원리를 등장 빈도순으로 집계
5. 원리별 정의와 산업 사례 4건 조회 (`lookup.py principle --cases`)
6. 사용자 시스템에 맞춘 아이디어를 원리마다 1~3개 작성

**물리적 모순** ("X는 이유 A로 P여야 하고 이유 B로 P가 아니어야 한다"):

1. 한 특성에 걸린 상반된 두 요구와 각각의 이유로 다시 쓰기
2. 각 요구가 어디서, 언제, 누구·무엇에 대해, 어느 방향으로, 어느 수준에서 필요한지 확인 (입력에 없으면 한 번에 하나씩 질문)
3. 두 요구가 겹치지 않는 분리 유형 선택: 공간, 시간, 관계(조건), 방향, 시스템 수준
4. 연계 원리 조회(`lookup.py separation`) 후 그 분리를 구현하는 아이디어 작성

**모호한 입력이나 해법만 설명한 글**(특허 초록 등): 모순을 추측하지 않고 질문을 한 번에 하나씩, 최대 5개까지 해서 모순을 찾습니다. 독립 특허 벤치마크에서 추측은 우연 수준이었습니다(데이터 상태 참고).

## 예시

실제 실행을 줄인 것입니다(v0.3.0, 모델 `claude-opus-5-5`, 모순 문장 확인은 미리 받은 상태). 원리 5개 중 첫 원리의 아이디어만 옮겼습니다.

```
/triz 전동 킥보드 최고 속도를 올리고 싶은데 배터리가 너무 빨리 닳아요.
```

> **파라미터 매핑**
>
> | 구분 | 파라미터 | 근거 |
> | --- | --- | --- |
> | 개선 | #9 속도 | 올리려는 것이 킥보드의 최고 속도다 |
> | 악화 | #19 에너지 사용 (움직이는 물체) | 움직이는 킥보드가 배터리 전력을 더 많이 쓴다 |
> | 악화 | #15 작동 지속 시간 (움직임) | 한 번 충전으로 달리는 시간과 거리가 줄어든다 |
> | 악화 | #22 에너지 손실 | 고속에서는 공기저항, 모터·컨트롤러 발열 같은 낭비가 커진다 |
>
> **추천 원리 (행렬 조회 결과)**: `lookup.py matrix --improve 9 --worsen 19,15,22` (빈 조합 없음, 경고 없음)
>
> | 순위 | 원리 | 등장 횟수 |
> | --- | --- | --- |
> | 1 | #35 매개변수 변화 | 3 |
> | 2 | #19 주기적 조치 | 2 |
> | 3 | #8 평형추 | 1 |
> | 4 | #3 국소적 품질 | 1 |
> | 5 | #14 구면화 | 1 |
>
> **원리 #35 매개변수 변화**
> - *온도 변경(하위 원리 4):* 배터리와 모터 온도를 관리합니다. 추울 때는 셀을 예열해 내부저항을 줄이고, 고속 주행 중에는 모터와 컨트롤러를 식혀 발열 손실을 줄입니다.
> - *상태 변경(하위 원리 1):* 컨트롤러와 모터 코일의 열을 히트파이프나 상변화 소재로 빼내 고속에서도 출력을 줄이지 않고 효율을 유지합니다. (사례: 전기·전자 분야의 히트파이프)
>
> **다음 단계**: 속도대별 소비전력(Wh/km)을 재서 손실의 주원인이 공기저항, 구름저항, 모터·컨트롤러 효율 중 무엇인지 가려 보세요. 국내 PM 최고 속도 규정(25km/h)도 확인해야 합니다.

표의 번호는 모두 그 실행에서 `lookup.py`가 출력한 값입니다. "사례"는 스크립트가 원리마다 돌려주는 산업 사례(`principle --cases`)이며, 답은 사례를 아이디어로 그대로 옮기지 않고 비유로만 씁니다.

## 동작 방식

| 단계 | 담당 |
| --- | --- |
| 문제 이해, 모순 유형 판별, 파라미터·분리 유형 선택, 아이디어 작성 | Claude |
| 파라미터·원리 검증, 행렬·분리 원리 조회, 순위 집계 | `skills/triz-analysis/scripts/lookup.py` |

`lookup.py`(Python 3.9+, 표준 라이브러리만, 네트워크 호출 없음)는 JSON을 출력합니다.

```
python3 skills/triz-analysis/scripts/lookup.py matrix --improve 9 --worsen 19,22
python3 skills/triz-analysis/scripts/lookup.py principle --id 35,15 --cases
python3 skills/triz-analysis/scripts/lookup.py param --search 속도
python3 skills/triz-analysis/scripts/lookup.py separation --type time,space
python3 skills/triz-analysis/scripts/lookup.py validate
```

오류는 stderr의 JSON과 종료 코드(2 인자 오류·알 수 없는 분리 유형, 3 범위 초과, 4 동일 파라미터, 5 데이터 오류)로 반환합니다. 빈 셀은 오류가 아니라 `empty_pairs`에 담깁니다.

스킬 폴더 안에 `data/`와 `scripts/`가 함께 있어서 스킬 폴더만 따로 Claude.ai에 올려도 동작합니다.

## 데이터 처리

- **입력한 내용.** 설명한 문제는 다른 메시지와 마찬가지로 사용자의 Claude 세션에서 Claude가 처리하며, 사용자의 Claude 계정 약관을 따릅니다. 플러그인은 이를 따로 수집·저장하거나 다른 곳으로 보내지 않습니다.
- **스크립트가 하는 일.** `lookup.py`는 함께 들어 있는 `data/*.json`만 읽어서 JSON을 터미널에 출력합니다. 네트워크 호출, 환경 변수·자격 증명 읽기, 파일 쓰기를 하지 않습니다.
- **플러그인에 없는 것.** 훅, MCP 서버, 백그라운드 프로세스, 텔레메트리, 계정·API 키가 없습니다.
- **파일을 쓰는 경우.** 보고서 저장을 요청했을 때(`/triz ... --save` 또는 "저장해줘")만 현재 디렉토리(또는 지정한 경로)에 Markdown 파일 하나를 만들며, 같은 이름의 파일은 덮어쓰지 않습니다.
- **개인정보.** 이 플러그인은 개인정보를 읽거나 보관하도록 만들어지지 않았습니다. 문제 설명에 개인정보나 기밀을 넣지 마세요. 다른 프롬프트와 똑같이 Claude에 전달됩니다.

## 다루지 않는 것

TRIZ는 이 플러그인보다 훨씬 넓습니다. 이 플러그인은 기술적 모순(모순 행렬 → 40 발명 원리)과 물리적 모순(분리 원리)을 다룹니다. 다음은 **하지 않습니다.**

- 모순을 알기 전의 문제 분석: 기능 분석, 트리밍, 근본 원인·숨은 자원 분석
- 76가지 표준해와 물질-장 분석
- ARIZ, 기술시스템 진화 법칙, 기능지향검색

40 발명 원리는 아이디어를 떠올리게 하는 체크리스트이지 정답 보증이 아닙니다. 결과가 이상하면 원리를 의심하기 전에 매핑이나 문제 정의를 먼저 다시 보세요.

## 데이터 상태

| 데이터 | 상태 |
| --- | --- |
| 모순 행렬 | 서로 독립적으로 옮겨 적은 세 계열(영문 전사본 계열, MATRIZ 지식베이스, 러시아어 표)의 3분의 2 표결로 1248셀 전부를 확정했습니다. 지금은 보류된 셀이 없고, 앞으로 분쟁이 생기면 `unverified_cell` 경고로 알리는 장치는 그대로 있습니다. 인쇄본 원문과의 대조는 인쇄본을 구할 수 없어 하지 못했습니다. |
| 파라미터 39개, 원리 40개 | 번호·명칭은 교차 검증, 정의·하위 원리·예시는 이 프로젝트에서 직접 작성. 산업 사례 160건(원리당 4건, 6개 분야)도 비유용으로 직접 작성했고 회사·제품 이름은 쓰지 않음. AI 검토(Claude 두 번)만 거쳤고 원어민·분야 전문가 검토는 아직입니다. 다른 계열 모델 검토는 예정입니다. 오류는 GitHub 이슈로 알려 주세요 |
| 분리 원리 | 5개 유형과 유형별 연계 원리는 MATRIZ TRIZ 지식베이스(CC BY 4.0)를 따르며, 공개된 전사본에서 가져와 MATRIZ 위키 원문과 대조했습니다(다섯 목록 모두 일치). 질문·예시는 직접 작성했습니다. 이 목록은 문헌마다 다르므로 믿을 만한 한 가지 해석으로 보세요 |
| 매핑 정확도 | 평가 케이스 32건 블라인드 실행: 실행별 Top-3 적중 96~100%(기대값 수정 후 전체 91/93), 원리 번호 환각 0건, 보류된 셀에 걸렸을 때 9/9 사용자에게 알림. 표본이 작고 기대값을 작성자가 정했으며 실행 간 변동이 있으므로 스모크 테스트로 보세요. **독립 특허 벤치마크(TRIZBench)에서는 Hit@3가 첫 30건 10%, 겹치지 않는 75건 13%로, 가장 흔한 정답 3쌍만 찍는 기준선(9~16%)과 비슷한 수준이었습니다.** 사용자가 트레이드오프를 직접 말할 때 가장 잘 맞고, 해법만 설명한 글에서는 기대하기 어렵습니다 (`tests/eval/results-v0.1.md`). v0.2 변경 뒤에도 기술적 모순 케이스는 30/32를 맞혔습니다 |
| 물리적 모순 | 평가 케이스 10건 블라인드 실행: 조회한 분리 유형이 기대와 맞은 비율 명령 모드 9/10, 자연어 8/10(답안에 적은 유형까지 치면 10/10), 원리 환각 0건. 작성자가 쓴, 요구가 분명한 케이스라 스모크 테스트로 보세요 (`tests/eval/results-v0.2.md`) |

위 정확도 수치는 v0.2 기준 측정값입니다. v0.3에서는 다시 측정하지 않았습니다. v0.3의 산업 사례는 파라미터 매핑이 끝난 뒤에만 쓰이고 원리 번호를 담지 않으며, 아이디어 품질이 나아졌다고 주장하지 않습니다.

출처, 검증 방법, 미확정 셀은 [DATA_SOURCES.md](DATA_SOURCES.md)에 있습니다. TRIZ 결과는 아이디어의 출발점이지 정답이 아닙니다. 매핑을 점검하고 아이디어를 검증한 뒤에 활용하세요.
