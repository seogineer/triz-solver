## 모순 정의
데이터 전송 시스템의 전송 속도(처리량)를 높이면 전송 중 데이터 오류와 손실이 늘어난다.

## 파라미터 매핑
| 구분 | 파라미터 | 근거 |
| --- | --- | --- |
| 개선 | #9 속도 | 전송 속도는 작업이 진행되는 빠르기다. |
| 개선 | #39 생산성 | 단위 시간당 전송량(처리량)이 늘어난다. |
| 악화 | #24 정보 손실 | 데이터 유실과 노이즈가 늘어난다. |
| 악화 | #27 신뢰성 | 오류 때문에 정상 전송 능력이 떨어진다. |

조합 4개를 모두 조회했다. 빈 셀과 `unverified` 항목은 없다.

## 적용 아이디어
### 원리 #13 역발상
- 아이디어 1: 송신 측이 데이터를 계속 밀어 넣는 방식을 바꾼다. 수신 측이 준비된 만큼만 요청하게 한다. 이는 "문제에서 요구하는 동작 대신 반대 동작을 한다"를 적용한 것이다. 수신 버퍼가 넘치는 손실이 줄어든다. (사례: software)
- 아이디어 2: 오류를 막는 데 집중하지 않는다. 오류를 허용하고 빠르게 복구하는 쪽으로 설계한다. 손상된 조각만 재전송한다.

### 원리 #35 매개변수 변화
- 아이디어 1: 변조 방식이나 신호 밀도를 조건에 따라 바꾼다. 채널 상태가 좋으면 고속 방식을 쓴다. 노이즈가 늘면 저속·고신뢰 방식으로 낮춘다. 이는 "유연성의 정도를 바꾼다"를 적용한 것이다.
- 아이디어 2: 전송 속도와 전송 창(window) 크기를 오류율에 따라 동적으로 조절한다. 오류율이 임계값을 넘으면 속도를 낮춘다.

### 원리 #11 사전 대비
- 아이디어 1: 순방향 오류 정정(FEC) 부호를 데이터에 미리 붙인다. 수신 측이 재전송 없이 오류를 복구한다.
- 아이디어 2: 중요한 데이터는 사본을 미리 보내거나 보관한다. 이는 "신뢰성이 낮은 대상에는 보호 수단을 미리 마련한다"를 적용한 것이다. (사례: software의 대기 서버)

### 원리 #1 분할
- 아이디어 1: 큰 데이터를 독립적인 작은 패킷이나 청크로 나눈다. 오류가 나면 해당 청크만 다시 보낸다. 이는 "독립적으로 움직이는 부분으로 나눈다"를 적용한 것이다.
- 아이디어 2: 전송 경로를 여러 개로 나눈다. 경로마다 속도를 낮춰도 합계 처리량은 유지된다. 한 경로의 오류가 전체로 번지지 않는다.

### 원리 #26 복사
- 아이디어 1: 실제 데이터를 보내기 전에 가벼운 시험 패킷(프로브)을 보낸다. 시험 결과로 채널 품질을 확인한 뒤 본 전송 속도를 정한다. 이는 "단순하고 싼 복제본을 쓴다"를 적용한 것이다.
- 아이디어 2: 전체 데이터 대신 체크섬이나 해시 같은 요약본을 비교한다. 오류 검출 비용이 줄어든다.
